# Russian archive checkpoint contract

The archive workflow reads `collection/russian/roster.json` from the repository
and `archive-manifest.json` plus all EPUB and QA bundles from a GitHub Release
tag (default `bb-russian-checkpoints`). This Release stores production inputs;
it is not the final collection archive. Do not use Actions artifacts or signed
blob links as checkpoint inputs. Every asset is identified by its name, byte
size and SHA-256; replacing an asset without updating the manifest fails.

The repository roster must be a frozen JSON object with
`expected_title_count: 186` and `titles`, an array ordered by `rank` 1–186.
Each entry has `rank`, `title`, and `author`. Commit the real canonical roster;
do not generate missing titles to satisfy the count.

The Release `archive-manifest.json` has this shape (showing one title only):

```json
{
  "schema_version": 1,
  "checkpoint_tag": "bb-russian-checkpoints",
  "expected_title_count": 186,
  "roster_sha256": "<sha256 of committed roster.json bytes>",
  "master_sha256": "<sha256 of latest approved Master bytes>",
  "release_state": "RELEASED",
  "titles": [
    {
      "rank": 1,
      "title": "<exact frozen title>",
      "author": "<exact frozen author>",
      "status": "RELEASED",
      "epub_asset": "001_<name>.epub",
      "size": 123456,
      "sha256": "<sha256 of exact final EPUB bytes>",
      "qa_asset": "001_qa.zip",
      "qa_sha256": "<sha256 of QA bundle bytes>"
    }
  ],
  "follow_on_rebuilds": [
    {"rank": 1, "title": "Война и мир", "sha256": "<final EPUB SHA-256>"}
  ],
  "collection_qa": {
    "asset": "collection_qa.zip",
    "sha256": "<sha256 of collection QA bundle bytes>"
  }
}
```

The real manifest needs 186 title entries and exactly six follow-on entries:
`Война и мир`, `Мастер и Маргарита`, `Анна Каренина`, `Три мушкетёра`,
`Моби Дик`, and `Мы`. Each follow-on entry binds the final rank and EPUB hash.
Assets must have unique names. ZIP bundles use safe relative member paths.

Each title `qa_asset` ZIP contains `report.json` with `epub_sha256`,
`master_sha256`, and `gates`. The gates object contains all sixteen QA-02 keys
named in `scripts/bb_russian_archive.py`. Every gate is an object with
`state: "PASS"`, `epub_sha256` matching the EPUB, `evidence_path` naming a
member of the same QA ZIP, and `evidence_sha256` matching that member's bytes.
These reports must be generated by the actual current-Master audits; a PASS
label by itself does not prove literary or visual compliance.

The `collection_qa.zip` also contains `report.json`, with `roster_sha256`,
`master_sha256`, and `titles_sha256`. Compute `titles_sha256` from the manifest's
`titles` array with UTF-8 JSON serialization using `ensure_ascii=False`,
`sort_keys=True`, and `separators=(",", ":")`. Its `gates` dictionary contains
`roster_reconciliation`, `follow_on_rebuilds`, `master_audit`,
`rights_and_sources`, and `final_byte_validation`. Each is PASS and has an
`evidence_path` and matching `evidence_sha256` inside the collection QA ZIP.

Populate the roster and checkpoint Release only from approved final bytes and
real evidence. Then run **Actions → Boundary Bay Russian Collection 186 EPUB
Archive → Run workflow** on the default branch, setting `checkpoint_tag` if
different. Any missing/blocked/review title, absent evidence, wrong digest,
EPUBCheck warning or error, or archive extraction mismatch fails before the
final artifact upload. The job produces independent ZIP parts under 750 MiB
of EPUB payload each, `SHA256SUMS.json`, and a copy of the checkpoint manifest.
